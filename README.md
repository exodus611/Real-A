# Кирьят-Гат: цены на новые квартиры, их изменение и все районы реновации

Источник цен — **реестр сделок налогового управления Израиля** (система «Карман»,
`nadlan.taxes.gov.il`): 3 844 200 сделок с 01.01.1998 по 17.09.2026, 1336 населённых пунктов.
Это реальные заявленные цены сделок, а не оценки и не льготные лотереи.

Плюс три слоя, которые превращают кадастровые номера в понятное:

* **адресный слой «נדל״ן לעם»** — улицы, почтовые индексы, координаты и статистические
  районы ЦСБ для каждого участка. Покрыто **76,1% сделок** Кирьят-Гата (14 880 из 19 566,
  1 399 участков из 1 627). Было 9%, стало 76%.
* **GIS-шейпфайл минстроя** с границами всех 976 объявленных комплексов реновации страны —
  поэтому по каждому комплексу видно, какие именно улицы в него входят.
* два датасета минстроя и РМАИ: состав комплексов реновации и всё, что ещё построят.

## Быстрый старт

```bash
cd projects/israel-watch
python3 server.py --port 8000 --city "קרית גת"
# открыть http://localhost:8000
```

Другой город — полем в панели или так:

```bash
python3 market.py --city "באר שבע"
```

Проверено на `קרית גת`, `באר שבע`. Работает для любого из 1336 населённых пунктов реестра.

Отдельно, без панели:

```bash
python3 geo.py --city "קרית גат"            # улицы, индексы, районы ЦСБ  (первый запуск ~6 минут)
python3 renewal_geo.py --city "קרית גат"    # границы комплексов и какие улицы в них
python3 geo.py --parcel 2812/349            # один участок: улица, точка, индекс, район
```

`geo.py` копит кэш в `analysis/geo_<код>.json`: прерванный запуск продолжает с того же места,
уже полученные участки не перезапрашиваются. Дальше сборка идёт из кэша за секунды.

Время первого прохода пропорционально числу участков со сделками, а не числу жителей:

| Город | Участков | Первый проход | Улиц нашлось |
|---|---|---|---|
| קרית גת (с 2012) | 1 627 | ~6 минут | 1 399 (86%) |
| באר שבע (с 2018) | 4 605 | ~17 минут | 94% на первых 500 |

Для сравнения: постраничная выгрузка самих сделок по Беэр-Шеве (114 012 сделки)
при лимите 20 запросов в минуту не проходит вообще — поэтому все медианы
и считаются на сервере, а не локально.

### Про «чистую» цену улицы

Один кадастровый участок может стоять на двух-трёх улицах сразу (угловой, или комплекс
на две стороны). Реестр сделок не публикует под-гуш, поэтому сделку такого участка
невозможно приписать одной улице. Участок 2909/136 на 275 сделок стоит одновременно
на נחל ירקון и שד לכיש — и в одиночку задавал обеим улицам одинаковую медиану ₪10 345/м²,
хотя на נחל ירקон всего 4 участка, а на שד לכיש 25.

Поэтому цена каждой улицы посчитана дважды: со спорными участками и **без них**
(«чистая» — только участки, стоящие на одной улице). В таблице и на графиках используется
чистая; спорные участки помечены `±N`. У נחל ירקון разница составила ₪10 345 → ₪11 305,
у שד גת 15 спорных участков из 72.

Видно главное: **единственный реально работающий комплекс «שבטי ישראל» — это улица נפתלי**,

легко оказывается за границей комплекса, который режет его пополам. Порог «в комплексе» —
50% площади участка, 5–50% — «на границе».

### Что происходит в 2026-м — и почему это не «цены упали на четверть»

Поквартально перелом виден точно:

```
2025-Q2   ₪20 165/м² ·  51 сделка
2025-Q3   ₪14 551/м² · 156 сделок   ← здесь
2025-Q4   ₪13 987/м² · 262 сделки
2026-Q1   ₪17 164/м² · 337 сделок
2026-Q2   ₪13 746/м² · 458 сделок
2026-Q3   ₪13 564/м² · 251 сделка
```

Распределение сделок по полосам цены объясняет причину — рынок **расслоился**:

| Полоса ₪/м² | 2024 | 2026 |
|---|---|---|
| 12 000–14 999 | 2,6% | **66,4%** |
| 17 000–22 999 | **85,2%** | 22,8% |

То есть в 2024-м почти все новые квартиры продавались в ₪17–23 тыс/м², а в 2026-м две трети сделок
ушли в ₪12–15 тыс/м², при этом верхняя полоса почти не сдвинулась. Медиана из-за этого падает на 29%,
но это смещение структуры сделок в более дешёвый сегмент, а не обесценивание конкретной квартиры.

Совпадает с общестрановой картиной: по данным ЦСБ доля сделок с государственным субсидированием
выросла с 28,8% (февраль–март 2026) до 38,7% (март–апрель 2026).

Вторичка при этом ведёт себя иначе — ₪15 938/м² в 2026 против ₪16 629 в 2025, то есть почти без изменений.

## Telegram

Сообщение собирается то же самое, что видно на вкладке «Telegram» — 2 169 символов,
в лимит 4096 укладывается с запасом.

```bash
export WATCH_TELEGRAM_TOKEN="123456:ABC..."
export WATCH_TELEGRAM_CHAT="987654321"

python3 market.py --city "קרית גת"            # посмотреть, не отправляя
python3 market.py --city "קרית גת" --send      # отправить
```

### Расписание

`--schedule daily|weekly|monthly|quarter`, по умолчанию **quarter** (раз в квартал).
Цены на жильё быстрее не меняются, а реестр пополняется с задержкой, поэтому чаще смысла нет.

Скрипт сам решает, пора ли слать: состояние хранится в `last_digest.json`, так что из cron его
можно дёргать хоть ежедневно — сообщение уйдёт только когда истёк интервал.

```cron
0 8 * * * cd /путь/к/projects/israel-watch && python3 market.py --city "קרית גת" --send --schedule quarter >> digest.log 2>&1
```

`--force` отправит принудительно, независимо от срока.

### Отдельно — сторож изменений в датасетах

`watch.py` следит не за ценами, а за самими государственными датасетами и срабатывает сразу,
как только что-то поменялось: новый комплекс реновации, смена статуса комплекса, новый план
застройки, изменение числа квартир.

```bash
python3 watch.py --init --city "קרית גת"   # базовый снимок
python3 watch.py --city "קרית גת"          # код возврата 1 = что-то изменилось
```

Проверено намеренно испорченным снимком: девять подделанных изменений пойманы все.

## Как устроен доступ к данным

Прямой сайт реестра `nadlan.gov.il` защищён **reCAPTCHA Enterprise** — обходить капчу я не стал.
Вместо этого используется полная копия реестра, которую держит `over.org.il`: те же данные
с того же `nadlan.taxes.gov.il`, но через обычный SQL-интерфейс без ключей.

```
GET https://www.over.org.il/api/append/{dataset_id}/datastore_search_sql?sql=...
```

Ограничения движка, на которые пришлось проектировать:

| Ограничение | Следствие |
|---|---|
| **20 запросов в минуту**, дальше HTTP 429 | постраничная выгрузка 26 тысяч строк города не проходит |
| `percentile_cont(0.5) WITHIN GROUP` работает | поэтому все медианы считаются **на сервере**: годовой разрез — один запрос |
| Все колонки — **текст** | `avg(deal_amount)` падает; нужно `deal_amount::numeric` |
| Колонки `_id` **нет** | курсорная пагинация невозможна, только OFFSET |
| Потолок ответа **1000 строк** | дальше `truncated=true` и строки молча обрезаются. Участков в городе больше тысячи (в Кирьят-Гате 1627 с 2012 года), поэтому в `geo.q_parcels` сделана настоящая постраничность с детерминированным `ORDER BY count(*) DESC, gush, chelka`. Без OFFSET часть участков просто потерялась бы |
| `percentile_cont` без `::int` | возвращает текст в экспоненциальной записи — «9.5E+5» |
| Даты текстом `DD/MM/YYYY` | год — `substr(deal_date,7,4)`, сортировка — склейкой подстрок |

### Адресный слой — другие эндпоинты и другие ограничения

```
GET /api/nadlan/parcel/{gush}/{helka}?fields=identity,streets,point,zip,stat_area&deals=false
GET /api/nadlan/lookup?gush=…&helka=…          # то же + сделки участка
GET /api/nadlan/streets?q=…&settlement=2630    # справочник улиц города
GET /api/nadlan/stats                          # счётчики покрытия по стране
GET /api/tables/{table}/features?bbox=min_lon,min_lat,max_lon,max_lat&columns=…&limit=5000&offset=…
```

| Ограничение | Следствие |
|---|---|
| `/api/nadlan/*` **не троттлит** так, как SQL-движок | 12 запросов подряд прошли по 0,5 с без единого 429 → все 1627 участков города за ~6 минут |
| `fields=` обязателен осмысленно | `deals=false` отсекает самый тяжёлый блок: на участке башни бывает до 1850 сделок |
| **`POST /api/tables/sql` и `/api/tables/export.csv` закрыты авторизацией** (403 `Not authenticated`) | скрестить реестр сделок с адресами одним SQL-запросом не выходит; джойн делается локально в Python по ключу гуш/хелька |
| `/api/tables/{table}/features` — **публичный** | оттуда берутся и полигоны комплексов, и полигоны участков, сразу в WGS84 |
| `limit` до 5000, дальше `exceededTransferLimit` + `offset` | участки города (15 386 в bbox) тянутся тремя страницами |
| Ответ слоя содержит `zip5: ["00000"]` | это заглушка, не индекс: 394 участка города из 1627. Отфильтровано |

Отчёт по городу целиком — **9 SQL-запросов + 1627 обращений к адресному слою**, около 90 секунд
при тёплом кэше улиц и около 6 минут при холодном.

## Решения, которые приняты осознанно

**Новые и котлован разделены.** У покупки на этапе котлована поле «год постройки» хранит
**плановый год сдачи** — в данных Кирьят-Гата есть 2029 и 2030. Смешанная медиана по «всем новым»
после 2022 года сравнивает готовые квартиры с заморозкой денег на три года вперёд.
Доля котлована среди новых: 0–7% до 2021 года, **58–75% с 2022-го**.

**Последний год всегда помечен как неполный**, а опорным берётся последний полный.

**Везде медиана, не среднее** — одна строка реестра может быть и квартирой, и целым зданием.

**Битые строки отсечены**: при доле `0.000` или площади, записанной на здание, цена за м² улетает
в ₪464 000 и ₪995 000. Фильтр ₪/м² от 2 000 до 150 000.

**Тип «מגורים» исключён**: в 68% таких строк нет площади и в 99% нет комнат — это земля и права,
не квартиры. Берутся `דירה בבית קומות`, `דירת גן`, `דירת גג` и три типа коттеджей.

## Ошибки, которые я сделал по дороге

1. **Сначала принёс не то.** Первая версия показывала льготные цены лотерей «Дира ба-анаха»
   вместо реальных сделок. Это другой продукт и другие деньги.
2. **Код города.** Кирьят-Гат — ЛАМАС **2630**, а 2600 — это **Эйлат**. В выборку молча
   подмешались 39 чужих строк. Теперь коды не зашиты в код, а берутся из справочника реестра,
   и при нескольких совпадениях выбирается то, где сделок больше.
3. **Написание города.** В реестре сделок «קריית גת» (с йудом), в датасетах минстроя «קרית גת»
   (без). Первая попытка дала ноль результатов по трём источникам — и это выглядело как
   «в городе ничего не происходит».
4. **Определение новой квартиры.** «Построена недавно» записывало весь котлован во вторичку.
5. **`resolve_city` была написана запутанно** и однажды вернула «не найдено» для города,
   который до этого находила. Переписана на простое нормализованное сравнение,
   проверена на 13 городах и двух написаниях.
6. **Справочник городов тянулся по сети при каждом запуске.** Из-за этого тот же
   `resolve_city` падал повторно, уже с валидным кодом в руках: сообщение
   «населённый пункт не найден» означало на самом деле «справочник не загрузился».
   Теперь справочник кэшируется на диск на 14 дней, ответ валидируется перед записью
   (непустой список, ≥500 строк, у первых строк есть название), а при сбое сети
   берётся даже просроченный кэш — коды городов не меняются.
7. **Ориентация обхода в отсечении полигонов.** `_convex_hull` возвращает обход против
   часовой, а Сазерленд—Ходжман здесь считает «внутри» при обходе клиппера по часовой.
   В результате любое пересечение выходило пустым: все 8 комплексов реновации
   отрисовались с нулём участков внутри, хотя геометрия и площади считались верно.
   Поймалось на контрольном примере из двух квадратов с заведомым перекрытием в четверть —
   без такого примера это выглядело бы как «в городе никто не живёт в зонах реновации».
8. **Одна медиана на две улицы.** Участок 2909/136 на 275 сделок стоит одновременно на
   נחל ירקון и שד לכיש и задавал обеим одинаковую медиану ₪10 345/м². Заметил только
   потому, что числа совпали до шекеля. Отсюда «чистая» цена улицы — без спорных участков.
9. **Индекс «00000».** Показался у 394 участков города, включая все крупные новостройки.
   Это заглушка слоя, а не почтовый индекс; настоящие индексы Кирьят-Гата начинаются с 82.

## Что добавить дальше

- **Номера домов.** Сейчас точность — улица, потому что газовый реестр связывает гуш-хелька
  только с улицей. Список адресов почты (`over_re_addresses`, 728 548 строк, 76% с точкой)
  содержит и дома, и `parcel_key`, но для Кирьят-Гата он пуст: там 42% адресов страны
  вообще без координат, и для малых городов привязки к участку нет. Поднять это можно
  только через городскую адресную GIS-слоя — `point_source='municipal_<слой>'`,
  и публикуют её не все муниципалитеты.
- **Возраст и этажность домов по улицам.** В слое `gaztir_41720377` («газовый реестр
  недвижимости») на каждое здание есть `BuildingYear`, `BuildingFloors`, `EstimatedAppartments`,
  `SubParcelNum`. Это прямой признак кандидата на реновацию: старые малоэтажные дома.
  Слоя без геометрии, поэтому построчно доступен только через авторизованный
  `POST /api/tables/sql` — публично из него отдаётся 20 строк примера.
- **Индекс ЦСБ по Южному округу** — общерыночный фон. API ЦСБ из этой песочницы отдаёт
  HTML-заглушку; с машины в Израиле, скорее всего, заработает.
- **Алерт «ваш дом в комплексе реновации»** — по адресу или гуш/хелька. Самое сильное событие
  из всех, что здесь отслеживаются.
